01 / Features

Twelve capabilities, four layers

From Telegram intake to a tagged MP3 on disk — every stage is automated, observable, and crash-tolerant.

Telegram Bot

Batch URL Extraction

Any message can carry multiple YouTube, Shorts, or music.youtube.com links. Every unique URL is extracted, deduplicated, and queued in a single pass.

Per-URL Failure Alerts

A link that exhausts all retries triggers an immediate standalone Telegram warning with a short error, so no failure passes silently.

Download Engine

4 Parallel Async Workers

An asyncio.Queue is drained by four independent coroutines, each running yt-dlp and ffmpeg off the event loop.

Skip-Existing Deduplication

Downloads are pre-checked against the output directory and the tasks table. Duplicates are marked skipped, never re-fetched.

Optional cookies.txt

If cookies.txt sits next to main.py it is passed transparently to yt-dlp. If it is absent, the pipeline proceeds without authentication.

Single-Command Launch

python main.py boots the Telegram bot, FastAPI server, and worker pool together through asyncio.gather — one process, one shutdown path.

Audio Processing

Cover Art Embedding

ffmpeg maps art.png as Cover (Front) with id3v2_version 3, so every MP3 ships with your custom artwork.

Deterministic Output

Finished files are written as {title}-{artist}.mp3 into ~/Downloads/Music, sanitized for the host filesystem.

Data & Reliability

Real-Time Dashboard

A local FastAPI dashboard streams worker state, queue depth, daily stats, and logs over WebSocket every second.

Six-View SPA

Dashboard, Queue, History, Settings, Terminal, and Logs — client-side routed with zero page reloads.

SQLite Persistence

Queue, history, editable settings, and daily counters survive restarts in a single qazan.db file.

Crash-Tolerant Queue

Interrupted downloading or processing tasks are reset to pending and re-enqueued automatically on boot.

03 / Installation

Seven steps from clone to pipeline

Windows and Linux/macOS commands are provided where they differ. No build step, no containers, no cloud accounts.

Python3.11+ (3.12 recommended)Verify with python --version.

  1. 01

    Clone the repository

    Fetch the project and move into its root directory.

    git clone https://github.com/QarabaiErooom/QAZAN-MP3-MUSIC-DOWNLOADER.git
cd qazan-mp3-downloader
  2. 02

    Create and activate a virtual environment

    Keep the project dependencies isolated from the system Python.

    python -m venv .venv
.venv\Scripts\activate
    python3 -m venv .venv
source .venv/bin/activate
  3. 03

    Install Python dependencies

    Upgrade pip, then install the pinned requirements.

    pip install --upgrade pip
pip install -r requirements.txt
  4. 04

    Install Deno

    yt-dlp-ejs requires Deno at runtime. Install it once and let yt-dlp pick it up from PATH. Verify with deno --version.

    irm https://deno.land/install.ps1 | iex
    curl -fsSL https://deno.land/install.sh | sh
  5. 05

    Add your cover art

    Place a square PNG at the configured path. 500×500 or larger is recommended. If the file is missing, the pipeline still runs — you just get an MP3 without embedded art.

    C:\Users\Erom\Downloads\QAZAN MUSIC\art.png
  6. 06

    Configure config.py

    Edit the four values you actually need. Everything else — bitrate, worker count, artist, retries — is editable later from Dashboard → Settings.

    BOT_TOKEN    = "123456789:AAExampleTokenFromBotFather"   # from @BotFather
ART_PATH     = r"C:\Users\Erom\Downloads\QAZAN MUSIC\art.png"
OUTPUT_DIR   = r"C:\Users\Erom\Downloads\Music"
COOKIES_PATH = "cookies.txt"                              # optional
  7. 07

    Run

    One command boots the Telegram bot, the FastAPI server, and the four-worker queue concurrently. On Windows you can also double-click start.bat.

    python main.py

    The dashboard becomes available at http://127.0.0.1:8000 immediately. The server binds only to localhost.

04 / Usage

Send links, watch the pipeline

The Telegram bot is the intake; the browser dashboard is the observability layer. Nothing else is required.

A Telegram Bot

  1. Send /start to the bot. You will receive the intro message in Kazakh.
  2. Send any message containing one or more YouTube URLs — youtu.be, youtube.com/watch, youtube.com/shorts, and music.youtube.com are all supported. You can mix them in one message.
  3. The bot extracts every unique link, enqueues each as an independent task, and replies once with the queue acknowledgement.
  4. When every task in that batch reaches a terminal state, one consolidated summary arrives with totals, duration, and average throughput.
  5. Any URL that exhausts its retries triggers an immediate standalone warning, so you never wait for the batch to learn that one link failed.

06 / Architecture

One event loop, four workers

Telegram intake feeds an asyncio queue. Workers run yt-dlp and ffmpeg, persist state to SQLite, and FastAPI streams a snapshot to the browser every second.

Solid arrows show the download path. Dashed arrows show state reads and writes.

Module-by-module breakdown
  • main.py

    Single entry point. Boots logging, initializes the database, restores interrupted tasks, then runs asyncio.gather(bot, web, workers) so all subsystems share one event loop and one shutdown path.

  • config.py

    Holds every constant (BOT_TOKEN, paths, DEFAULT_SETTINGS), configures the file logger targeting system.log, and exposes human() for colorized Kazakh console lines plus the in-memory log ring buffer.

  • db.py

    Thin aiosqlite layer with three tables: tasks, settings, stats_daily. Provides enqueue_task, update_task_status, get_queue, get_history, get_dashboard_stats, cleanup_old_tasks, and value casting on read.

  • downloader.py

    The heart of the pipeline. Defines the WorkerPool supervisor, four persistent worker coroutines, yt-dlp and ffmpeg wrappers, the retry loop, and the Notifier bridge used by the Telegram module for per-URL failure alerts.

  • telegram_bot.py

    aiogram 3 dispatcher. Handles /start and any text message, extracts and deduplicates URLs, enqueues each as a DB row plus queue item, aggregates the chat's pending task IDs, and sends the final summary only once all of them reach a terminal state.

  • web.py

    FastAPI application with a single HTML route, REST endpoints for settings, queue, history, and logs, and the /ws WebSocket that pushes a full dashboard snapshot every second. Bound to 127.0.0.1 only.

  • templates/ · static/

    Vanilla SPA. No build step; the six views toggle via CSS classes, the WebSocket reconnects automatically, and settings changes route through a confirmation modal before hitting POST /api/settings.

08 / Project Structure

One file, one concern

09 / Reliability

Failures stay contained

A single bad URL never stops a worker, never stops the queue, and never stops the process.

  • Per-URL retry. Every task gets up to 3 attempts with a 5-second delay between each. The retry loop is scoped to a single task, never to the worker or the queue.
  • Immediate failure notifications. The moment a URL exhausts its retries, the originating Telegram chat receives a standalone message with the URL and a short error.
  • Queue isolation. A worker never propagates an exception to the pool. Every task runs inside its own try / except / finally block, and queue.task_done() fires unconditionally.
  • Skip-existing deduplication. A download is pre-checked against the filesystem and against tasks WHERE status = 'done'. Matching titles are marked skipped without consuming bandwidth.
  • Missing assets are non-fatal. No art.png means a warning and an audio-only MP3. No cookies.txt means the pipeline proceeds without cookies. Neither condition halts the pipeline.
  • Crash-tolerant restart. On boot, any task left in downloading or processing is reset to pending and re-enqueued, so a hard power-off never loses work.
  • Bounded logging surface. Tracebacks are written exclusively to system.log. Stdout receives only human-readable Kazakh lines, keeping the terminal and dashboard clean.
